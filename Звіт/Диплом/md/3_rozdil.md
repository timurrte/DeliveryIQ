# 3 РОЗРАХУНКОВИЙ РОЗДІЛ

## 3.1 Програмне забезпечення

Розроблена інформаційна система оптимізації маршрутів доставки «DeliveryIQ» реалізована як веб-застосунок із серверною логікою. Вибір програмного забезпечення обумовлений вимогами до швидкості розробки, наявності зрілих бібліотек для роботи з географічними даними та можливості створення інтерактивного інтерфейсу без залучення окремої фронтенд-команди.

### 3.2 Мова програмування та середовище розробки

Як основну мову програмування обрано Python 3.10+. Цей вибір зумовлений наступними чинниками:

– розвинена екосистема бібліотек для роботи з графами (NetworkX), геоданими (OSMnx, GeoPy, Shapely) та чисельних обчислень (NumPy);

– підтримка об’єктно-орієнтованої парадигми, що відповідає декомпозиції системи на класи `DeliveryStop`, `Vehicle`, `VehicleRoute`, `PackageDB`;

– висока продуктивність розробника завдяки динамічній типізації та лаконічному синтаксису;

– кросплатформність — застосунок працює як у Windows, так і в Unix-подібних системах без модифікації коду.

Інтегрованим середовищем розробки обрано Visual Studio Code з розширеннями Python, Pylance та GitLens. Контроль версій здійснювався за допомогою системи Git з локальним репозиторієм.

### 3.3 Використані бібліотеки та фреймворки

Для побудови системи задіяно набір зрілих open-source бібліотек, перелік яких зафіксовано у файлі `requirements.txt`:

– Streamlit (≥ 1.35) — фреймворк для побудови інтерактивного веб-інтерфейсу. Дозволяє створювати багатосторінкові застосунки без HTML/CSS/JavaScript-коду та забезпечує реактивне оновлення станів через механізм `st.session_state`;

– OSMnx (≥ 2.1) — бібліотека для завантаження, моделювання та аналізу вуличних мереж з OpenStreetMap. Використовується для отримання дорожньої мережі заданого міста та її подальшої обробки;

– NetworkX (≥ 3.2) — бібліотека для роботи з графами. Застосована для обчислення найкоротших шляхів алгоритмом Дейкстри під час побудови матриці часів подорожі;

– GeoPy (≥ 2.4) — клієнт до сервісу геокодування Nominatim. Перетворює адреси у пари координат (широта, довгота) та виконує зворотне геокодування;

– Folium (≥ 0.16) з плагіном `AntPath` — генератор інтерактивних карт на базі Leaflet.js з підтримкою анімованих маршрутів;

– streamlit-folium (≥ 0.20) — інтеграційний шар між Streamlit і Folium, що повертає клік-події з карти у Python-код;

– NumPy (≥ 1.26) — бібліотека векторних обчислень, використовується у генетичному алгоритмі для роботи з масивами хромосом;

– Shapely (≥ 2.0) — бібліотека геометричних операцій (буферизація, перевірка перетинів) для роботи з контурами міста;

– scikit-learn (≥ 1.4) — застосовується для кластеризації пунктів доставки методом k-means на етапі початкового розподілу замовлень між машинами;

– requests (≥ 2.31) — HTTP-клієнт для звернень до зовнішніх REST API (Mapbox Directions API).

Зберігання інформації про замовлення реалізовано на вбудованій у Python СКБД SQLite, що не потребує додаткового сервера.

## 3.4 Технічне забезпечення

Для коректної роботи системи на стороні сервера встановлено наступні мінімальні вимоги до апаратного забезпечення:

– Процесор: не нижче рівня Intel Core i5 (4 ядра, 2.4 ГГц) або еквівалентний. Обчислювальна складність генетичного алгоритму при популяції 50 особин та 150 поколіннях вимагає достатньої продуктивності одного потоку;

– Оперативна пам’ять: не менше 8 ГБ. Граф дорожньої мережі міста середнього розміру (наприклад, м. Дніпро) у форматі NetworkX MultiDiGraph займає 400–800 МБ під час обробки;

– Постійна пам’ять: не менше 2 ГБ вільного дискового простору для розгортання віртуального середовища Python, кешу графів `.graphml` та бази даних SQLite;

– Мережеве з’єднання: широкосмуговий доступ до мережі Інтернет зі швидкістю не менше 10 Мбіт/с для завантаження картографічних даних з серверів OpenStreetMap та звернень до Nominatim;

– Операційна система: Windows 10/11, Ubuntu 20.04+ або macOS 12+.

З боку клієнта достатньо будь-якого сучасного веб-браузера з підтримкою JavaScript (Google Chrome, Mozilla Firefox, Microsoft Edge) та з’єднання з сервером по локальній мережі або через мережу Інтернет.

## 3.5 Етапи проектування та виконання

Розробка системи виконувалася ітеративно за наступним планом:

1. Аналіз вимог. Сформульовано бізнес-задачу автоматизованого планування маршрутів доставки. Визначено функціональні вимоги: завантаження дорожньої мережі, ведення бази замовлень, побудова оптимальних маршрутів, візуалізація результатів.

2. Проектування архітектури. Здійснено декомпозицію системи на сім модулів (`app.py`, `geocoder.py`, `graph_builder.py`, `route_solver.py`, `vrp_solver.py`, `package_db.py`, `visualizer.py`) з чітко визначеним інтерфейсом між ними.

3. Розробка модуля побудови графа. Реалізовано функції завантаження мережі з OpenStreetMap, обрізки до найбільшої сильнозв’язної компоненти (LSCC) та обчислення часів подорожі для трьох режимів пересування — авто, велосипед, пішки.

4. Розробка модуля розв’язання TSP. Реалізовано чотири методи: «найближчий сусід», 2-opt, генетичний алгоритм та евристика Крістофідеса. Додано автоматичний вибір методу залежно від кількості пунктів.

5. Розробка модуля розв’язання VRP. Реалізовано двофазний декодер CVRPTW: фаза 1 — призначення замовлень транспортним засобам з урахуванням модальної сумісності та вантажомісткості; фаза 2 — незалежний TSP-генетичний алгоритм для кожної групи.

6. Розробка модуля бази даних. Реалізовано клас `PackageDB` на основі SQLite з підтримкою життєвого циклу замовлення (`PENDING → IN_TRANSIT → DELIVERED`).

7. Розробка модуля візуалізації. Реалізовано побудову інтерактивної карти на базі Folium з анімованим відображенням маршрутів за допомогою плагіну AntPath.

8. Розробка інтерфейсу. Створено чотиривкладочний інтерфейс Streamlit: «TSP», «VRP», «Менеджер пакетів», «Налаштування автопарку».

9. Тестування та налагодження. Проведено функціональне тестування на реальних даних по місту Дніпро та виправлено виявлені дефекти.

## 3.6 Інструкція користувача

Запуск системи виконується в командному рядку наступною командою:

```bash
streamlit run app.py
```

Після успішного запуску у браузері користувача автоматично відкривається веб-інтерфейс за адресою `http://localhost:8501`.

Порядок роботи з системою:

1. На вкладці «Налаштування автопарку» користувач задає характеристики транспортних засобів: тип (автомобіль / велосипед / пішохід), вантажомісткість у кілограмах, часове вікно доступності, кількість одиниць даного типу.

2. На вкладці «Менеджер пакетів» додаються замовлення на доставку. Для кожного пакета вказується адреса, вага, опціонально — часове вікно прийому клієнтом. Адреса автоматично геокодується через Nominatim з прив’язкою до міста Дніпро.

3. На вкладці «VRP» користувач вказує адресу депо (точки старту маршрутів), радіус завантаження графа (за замовчуванням 5 км) та натискає кнопку «Оптимізувати». Альтернативно, депо можна обрати кліком безпосередньо на карті (режим «Click-to-Add»).

4. Після завершення оптимізації відображається інтерактивна карта з кольоровими маршрутами для кожного транспортного засобу (зелений маркер — депо, червоні нумеровані маркери — пункти доставки). У бічній панелі виводиться сумарний час, кількість задіяних машин та список нерозподілених замовлень (якщо такі є).

5. На вкладці «TSP» реалізовано спрощений режим побудови маршруту для одного транспортного засобу без обмежень місткості — використовується для перевірки та порівняння алгоритмів.

## 3.7 Інструкція програміста

Розгортання системи на новій робочій станції виконується наступним чином:

1. Клонувати репозиторій проекту:
   ```bash
   git clone <repository_url>
   cd diplom
   ```

2. Створити та активувати віртуальне середовище Python:
   ```bash
   python -m venv venv
   venv\Scripts\activate   # Windows
   source venv/bin/activate  # Linux/macOS
   ```

3. Встановити залежності:
   ```bash
   pip install -r requirements.txt
   ```

4. (Опціонально) Задати ключ API Mapbox як змінну середовища для активації режиму матриць з урахуванням заторів у реальному часі:
   ```bash
   set MAPBOX_API_KEY=<your_key>   # Windows
   export MAPBOX_API_KEY=<your_key> # Linux/macOS
   ```

5. Запустити застосунок:
   ```bash
   streamlit run app.py
   ```

Модифікація території обслуговування. Місто за замовчуванням задано константою `DEFAULT_CITY = "Dnipro, Ukraine"` у файлі `app.py:64`. Зміна цього рядка переналаштовує всю систему на нове місто без додаткових модифікацій.

Налаштування параметрів генетичного алгоритму. У файлі `vrp_solver.py` визначено наступні константи: `POP_SIZE = 50` (розмір популяції), `N_GENERATIONS = 150` (кількість поколінь), `CROSSOVER_RATE = 0.85` (ймовірність схрещування), `MUTATION_RATE = 0.15` (ймовірність мутації), `ELITE_SIZE = 2` (розмір еліти), `TOURNAMENT_SIZE = 3` (розмір турніру). Збільшення `POP_SIZE` та `N_GENERATIONS` підвищує якість розв’язку за рахунок зростання часу обчислень.

Розширення системи. Додавання нового режиму пересування (наприклад, електросамокат) потребує: 1) додавання правил доступу у функцію `add_travel_times()` модуля `graph_builder.py`; 2) додавання значення константи швидкості до словника `SPEED_KMH`; 3) розширення поля `vehicle_type` у класі `Vehicle` модуля `vrp_solver.py`.

## 3.8 Тестування розробленого алгоритму

Методика тестування. Тестування розробленого програмного забезпечення проводилося у три етапи:

Модульне тестування — перевірка коректності окремих функцій: побудова матриці відстаней `build_distance_matrix()`, прив’язка координат до вузлів графа `nearest_node()`, кодування/декодування хромосом у генетичному алгоритмі. Перевірка проводилася на штучних тестових наборах із заздалегідь відомими еталонними розв’язками.

Інтеграційне тестування — перевірка взаємодії модулів у повному циклі оптимізації: геокодування адреси → завантаження графа → побудова матриць → виконання GA → візуалізація. Як тестові дані використано 5 наборів реальних адрес по місту Дніпро.

Функціональне тестування — перевірка відповідності поведінки системи функціональним вимогам: дотримання обмежень місткості, повага до часових вікон, гарантія відвідування кожного клієнта рівно один раз, коректна побудова маршруту з поверненням у депо.

## 3.10 Висновки до розділу

У розрахунковому розділі представлено програмну реалізацію розробленої інтелектуальної системи оптимізації розподілу вантажів «DeliveryIQ». Обґрунтовано вибір мови програмування Python 3.10+ та фреймворку Streamlit, визначено перелік допоміжних бібліотек (OSMnx, NetworkX, GeoPy, Folium) та сформульовано мінімальні вимоги до апаратного забезпечення.

Описано етапи проектування та виконання системи, а також надано детальні інструкції користувача та програміста, що забезпечують можливість самостійного розгортання та налаштування системи на новій робочій станції.

Проведене тестування на реальних даних по місту Дніпро підтвердило працездатність системи на масштабах від 5 до 100 замовлень. Порівняльний аналіз з класичними евристиками довів, що розроблений генетичний алгоритм дозволяє знаходити розв’язки на 8.9–34.3 % якісніші за традиційні методи, що повністю відповідає поставленій меті дослідження.
